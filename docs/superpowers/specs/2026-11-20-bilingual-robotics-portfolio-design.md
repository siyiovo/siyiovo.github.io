## 框架与部署

采用 Hugo 和 Hugo Profile 作为起始模板。Hugo 提供静态生成、多语言内容路由和 GitHub Pages 官方 Actions 部署方式；Hugo Profile 提供个人作品集常用的经历、技能、项目、画廊、简历和联系栏目。实现时锁定主题和 Hugo 版本，检查主题的中文样式、项目站点子路径和双语页面配对。

部署通过 GitHub Actions 构建 `public/` 并上传 GitHub Pages artifact。GitHub Pages 设置使用 GitHub Actions 来源。仓库不提交生成后的 `public/` 目录。站点地址通过构建配置提供，保证用户站点和项目站点都能正确生成资源链接。

## 页面与内容

### 首页

1. 首屏身份区展示姓名、头像、求职方向、简短介绍，以及 GitHub、邮箱和简历入口。
2. 核心能力按定位与建图、传感器融合、运动控制、机器人软件工程分组；未确认的技能不伪装成个人事实，初始内容以可编辑占位数据呈现。
3. 精选作品突出 `agx-retargeting` 和一个标为示例的 SLAM 定位项目。
4. 开源项目区展示 GitHub 上可核实的仓库名称、仓库介绍和代码链接；没有来源信息的个人经历不编造。
5. 联系区展示邮箱和公开职业主页链接。

### 项目详情

每个项目可包括摘要、背景与目标、本人职责、系统与算法方案、传感器或硬件、实验设计、量化结果、图片或视频、代码与文档链接。未知结果和外部链接不编造；占位项目使用明显的示例标识。

项目列表用简短摘要帮助招聘者扫描，点击后进入可分享的独立详情页。技术标签用于描述实际项目内容，不作为未经确认的技能背书。

### 双语页面

中文内容位于默认语言路径，英文内容位于英文语言路径。导航提供可键盘操作的中英文切换；切换时优先定位当前页面的对应语言版本，缺少对应翻译时回到该语言首页。页面使用正确的 `lang` 属性，并为语言页面生成对应的 SEO 元数据。

### 简历

简历内容按中文和英文分别预留文件位置。对应文件存在时显示下载链接；文件未上传时显示简历待更新状态，不输出空 href 或 404 链接。

## 视觉与交互方向

- 页面采用清晰、克制的工程作品集风格，面向招聘者快速阅读项目证据。
- 以明亮中性背景、深色正文和少量高辨识强调色构成多色层级，避免整页单色或渐变主导。
- 用项目图像、终端/地图/轨迹等真实作品素材说明技术工作；缺少素材时保留有尺寸约束的内容版位，不生成伪造的实验画面。
- 首页采用有节奏的全宽内容区和受控正文宽度，不堆叠装饰卡片；重复项目条目可以使用轻边界区分。
- 支持窄屏、键盘操作、可见焦点、足够颜色对比和减少动态效果偏好。
- 动效仅用于轻量导航和内容反馈，不影响阅读，不依赖悬停完成操作。
- 不把未确认的论文、学历、工作经历、性能数据或联系方式写成事实。

## 内容存放

- 双语个人资料和导航文案使用 Hugo 配置与语言翻译文件。
- 项目和经历使用 Hugo 内容页面及 front matter，中文和英文页面保持可识别的翻译关联。公开仓库的名称和说明以用户账号当前的 GitHub 页面为来源。
- 头像引用 GitHub 用户头像；若外部头像源不可用，页面仍保留头像容器和可访问文本。
- 简历放在静态资源目录，文件名区分语言。
- 将可替换的占位项目和未提供信息集中在易编辑的内容文件，避免散落在模板中。

## 验收标准

- 本地可以按仓库说明安装并构建 Hugo 网站。
- GitHub Actions 可以构建并发布到 GitHub Pages，资源在仓库子路径下仍可加载。
- 中文首页为根路径默认语言，英文首页可直达，语言切换可用。
- 首页和独立项目详情页展示 `agx-retargeting` 与明确标记的 SLAM 示例项目。
- GitHub 头像、邮箱和 GitHub 主页入口正确。
- 未上传简历时没有失效下载链接，上传后中英文简历入口分别有效。
- 桌面和移动视口均无横向溢出、遮挡或内容截断；主要操作可键盘访问。
- 未提供的经历和成果数据没有被杜撰。

## 自检

- 占位信息和真实个人事实有明确区分。
- 中文默认语言与英文切换目标一致。
- 项目详情内容模型覆盖招聘者评估技术作品需要的证据。
- GitHub Pages 部署设置与 Hugo 生成目录一致。
- 设计范围集中在个人求职作品集，不包含动态服务或非必要后台功能。
